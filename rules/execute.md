## 4. 任务执行规范

根据用户指令和现有需求、设计或代码契约实施变更；按需使用任务清单，而不要求创建缺失的阶段文件。

1. 阅读相关实现、调用方和模块指导，确认已授权的范围与现有依赖。
2. 聚焦需求修改，并针对变更行为和失败路径执行适当验证。遇到实质性歧义或关键取舍时向用户询问。
3. 如果使用任务清单，及时更新其状态。在 PR 或受版本管理的文档中记录必要的结果、验证证据和未解决限制；不要求为每个任务生成流水账日志。
4. 需要协作或长期保留的决策应放在受版本管理的文档或 issue 中；被忽略的 `.workflow/` 只用于本地工作。按照用户已给出的授权继续后续任务；用户要求暂停或审批时再停下。
